# Miro

Miro emulation covering the remote MCP server at `https://mcp.miro.com/` and the OAuth 2.1 authorization server on the same origin. The MCP endpoint is the origin root, so point a client at `<base>/`.

## OAuth

- `GET /.well-known/oauth-authorization-server` — RFC 8414 metadata. The issuer is `<base>/` with a trailing slash. It has no `jwks_uri` and no ID token fields
- `GET /.well-known/openid-configuration` — OIDC metadata that disagrees with the RFC 8414 document the way Miro's does: it advertises `token_endpoint_auth_methods_supported: ["none"]`, HS256 ID tokens, `revocation_endpoint`, and a nonstandard `audience`
- `POST /register` — Dynamic Client Registration, issuing a client secret
- `GET /authorize` — consent page with one sign in button per seeded user. S256 PKCE is required
- `POST /token` — `authorization_code` and `refresh_token` grants, `client_secret_post` or `client_secret_basic`. Refresh tokens rotate
- `POST /oidc/revoke` — token revocation

```bash
curl -X POST http://localhost:4021/register \
  -H "Content-Type: application/json" \
  -d '{"client_name":"My app","redirect_uris":["http://localhost:3000/callback"]}'
```

## ID tokens

When `openid` is granted, the token response includes an `id_token` signed HS256 with the client secret. Its claims are `iss`, `sub`, `aud` (the client id), `exp`, `iat`, and, when `email` is granted, `email` and `email_verified`.

Like real Miro, the ID token never carries `nonce`, even when the authorization request sent one. OIDC clients that send a nonce and validate it reject the response. Seed `id_token_nonce: echo` to make the emulator echo the nonce instead.

## MCP

`POST /` is a Streamable HTTP MCP server with the read only `board_search_boards` and `canvas_search` tools, backed by seeded boards. Any request without a valid bearer token, on any unknown path, answers `401 {"error":"Authentication required"}` with `WWW-Authenticate: Bearer resource_metadata="<base>/.well-known/oauth-protected-resource"`, matching Miro's gateway.

## Seed

```yaml
miro:
  id_token_nonce: omit
  users:
    - email: user@example.com
      name: Miro User
  boards:
    - name: Product Roadmap
      items:
        - type: sticky_note
          content: Ship OAuth for MCP
```

## Validation

Every token and revoke call records a ledger side effect with the client authentication method and outcome. Token issuance records whether the ID token nonce was omitted or echoed. Read it from `/_emulate/ledger`.
